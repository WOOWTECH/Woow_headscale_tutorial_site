第 4 章

建立使用者與 preauth key

在 Headscale 建立第一個使用者，並產生讓裝置加入網段的 preauth key。讀完這章，你會知道 user 與 key 的關係、怎麼安全地發一把「可撤銷的鑰匙」給新裝置。

先有使用者，才有裝置可加

Headscale 用「使用者（user）」來歸屬節點：每個加入網段的裝置，都要掛在某個 user 底下。而讓裝置「自己加入」的那把鑰匙，就是 preauth key。學會建立 user 與發 key，是讓第二台、第三台裝置進來的前提。

本章任務：建立一個 user、產生一把 preauth key、認識 key 的生命週期與安全。這些操作會改變控制層的狀態，動手前先想清楚用途。

user 與 preauth key 的關係

概念說明
user（使用者）節點的歸屬單位，一個 user 可以有多台裝置
preauth key（預授權金鑰）讓裝置免互動登入、直接加入某個 user 的一次性（或可重複）鑰匙
node（節點）加入後，每台裝置就是一個 node

流程是：先建 user → 為這個 user 產生 preauth key → 把 key 交給裝置 → 裝置用它加入 → key 用完撤銷。

一句話記住：user 是「歸屬」，preauth key 是「入場券」。入場券綁定在某個 user，用完就撕掉。

六步建立 user 與 preauth key

  1. 進入 Headscale 管理環境

    在 add-on 的終端或主機上，確認能執行 headscale 命令（第 3 章）。

  2. 建立 user

    執行 headscale users create <名稱>，例如 headscale users create family，建立一個叫 family 的 user。

  3. 確認 user 已建立

    用 headscale users list 查看，應看到剛建立的 user 在清單中。

  4. 產生 preauth key

    執行 headscale preauthkeys create --user family。命令會回傳一把 key，格式類似 headscale-xxxxx...。

  5. 視需要加期限與重複性

    可加 --expiration 24h 設 24 小時內有效、--reusable 讓它可重複使用（預設一次性）。

  6. 記錄並安全保存 key

    把回傳的 key 完整記下（用密碼管理器），不要貼在公開聊天或記事本。第 5 章會用到它。

key 只顯示一次：preauth key 通常在建立時才完整顯示，之後清單可能只顯示前綴。建立當下就要存好。

金鑰的生命週期與管理

動作命令（示意）時機
列出某 user 的 keyheadscale preauthkeys list --user family盤點有哪些鑰匙在外面
撤銷／過期headscale preauthkeys expire --user family <key>裝置加完、或鑰匙外流時
刪除 userheadscale users destroy <名稱>確認該 user 下的節點都處理好之後
key 就是鑰匙：誰拿到 preauth key，就能讓裝置加入你的網段。把它當最高機密；用完、或用錯對象，立刻撤銷。

怎麼組織 user 比較好

user 的劃分方式決定之後管理與 ACL 的難易。家庭或小團隊常見兩種做法：

做法適合優缺點
全家共用一個 user人少、互信高的家庭簡單，但難依人分權限
一人一個 user要區分權限、逐人管理較繁，但 ACL 能精準控管（第 7 章）
先簡後繁：剛開始可先用一個 user 跑通流程，等裝置多了、要區分權限，再拆成一人一個 user。

建立常見卡關

  1. users create 失敗

    可能是名稱已存在，或沒有管理權限。用 headscale users list 確認。

  2. preauthkeys create 回傳錯誤

    確認 --user 指定的 user 已存在；拼錯 user 名會失敗。

  3. key 沒存到就關了視窗

    key 多半不再完整顯示。最保險是撤銷舊的、重新產生一把新的。

  4. 裝置用 key 加不進去

    檢查 key 是否過期、是否綁對 user、是否已被用掉（一次性 key）。

建立常見問題

一個 user 可以加幾台裝置？
沒有硬性限制，一台家庭裝置、一組家人裝置都可歸在同一個 user，或用多個 user 分開管理。
preauth key 和登入帳密差在哪？
preauth key 是讓裝置「免互動」加入的鑰匙，適合自動化或 CLI 情境；互動登入則走瀏覽器授權。兩者都是授權裝置加入的手段。
key 可以設多久有效？
用 --expiration 設有效期限（如 24h、1h）。預設有效期限依 Headscale 設定而定，建議臨時用途都設短一點。
「--reusable」是什麼意思？
讓同一把 key 可以重複加入多台裝置；不加的話預設是「用一次就失效」。臨時發給單一裝置就不用加。
key 外流了怎麼辦？
立刻用 headscale preauthkeys expire 撤銷，再重新產生。已經用這把 key 加入的節點，到節點管理（第 6 章）確認是否要移除。
