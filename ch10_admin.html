第 10 章

管理員設定

認識 Headscale 的管理員設定：policy、DERP 中繼、使用者（namespace）與版本更新。讀完這章，管理員能維護整張私有網段、顧好備份，並安全地更新版本。

這章是給管理員的

Headscale 是整張私有網段的「大腦」。使用者的加入、誰能連誰、中繼伺服器、版本更新，都靠管理員維護。這章是給管理員（admin）的實務參考，一般使用者讀個概念就好。

管理動作影響整網：改 policy、動 DERP、更新版本，都會影響所有已連線的裝置。操作前先確認範圍，拿不準的不要亂改。

管理員管哪些東西

Headscale 的設定分幾塊，多數透過 config.yaml 與 CLI 管理：

區塊管什麼常見動作
policy（ACL）誰能連誰、哪些 port 放行查看、匯入、最小化存取
DERP中繼伺服器清單確認中繼可用、選用自架 DERP
使用者／namespace裝置歸屬的分群建立、列舉、管理
版本更新Headscale 本體升級看 release notes、備份後更新
CLI 是主要入口：Headscale 多數管理動作用 headscale 命令列完成；部分環境有 Web UI，但 CLI 最可靠、文件最齊。

五步做一次例行維護

  1. 列舉使用者與節點

    用 headscale users list 與 headscale nodes list 盤點目前有哪些帳號與裝置在網上。

  2. 檢視 policy

    用 headscale policy get 查看目前的存取規則，確認沒有開太寬（第 7、11 章）。

  3. 檢查金鑰

    用 headscale preauthkeys list 盤點尚未使用的金鑰，把用不到的撤銷。

  4. 看服務狀態

    確認 Headscale 服務正常、DERP 中繼可達、log 沒有反覆錯誤。

  5. 做備份

    把 config.yaml、policy、資料庫納入定期備份（本章後面詳述）。

最小權限：管理員能改 policy、刪節點。管理員帳號不要到處給，能少就少。

DERP 中繼伺服器

DERP（中繼協定）是當裝置間點對點直連失敗時的備援通道。正常情況下流量走點對點加密直連；連不通（例如對稱式 NAT、防火牆擋掉）時，才改走 DERP 中繼。

DERP 來源說明注意
內建 DERPHeadscale 可內嵌一個 DERP server最省事，但單點、效能有限
外部 DERP 清單設定檔指向一組公開 DERP延展性好，但流量經第三方中繼
自架 DERP自己跑 DERP server 並加入清單掌控最好，但要額外維護
判斷原則：點對點能直連就用直連（快、不走中繼）；只有連不通才靠 DERP。中繼只是備援，不是常態路徑。

使用者（namespace）管理

Headscale 用「使用者」（早期版本稱 namespace）把裝置分群。一個使用者名下可掛多個節點，policy 也能依使用者做區隔。新版把 namespace 更名為 user，概念相同。

  • 建立：headscale users create 名稱
  • 列舉：headscale users list
  • 用途：把「家人的裝置」和「工作裝置」分開管理，各自有獨立的金鑰與 policy 範圍。
別混用舊名：不同版本指令名有變（namespace ↔ user），操作前先看你的版本對應文件，不要照舊教學硬打。

備份 policy、金鑰與設定

Headscale 的「命脈」不是節點本身，而是這幾樣東西——重建整張網都靠它們：

  • config.yaml：伺服器設定（含 DERP、監聽、資料庫位置）。
  • policy（ACL）：存取規則，是安全的核心。
  • 資料庫：使用者、節點、金鑰等狀態。
備份要驗證：沒還原過的備份不算數。定期做一次還原演練，確認真的能把網段重建回來。

版本更新

  1. 先看 release notes

    更新前務必看官方 release notes，注意跨版本的破壞性變更（例如指令改名、設定檔格式變動）。

  2. 先備份

    備份 config.yaml、policy、資料庫後再更新，這是前提。

  3. 選離峰時間

    更新會短暫中斷控制層，選沒人用網的時段。

  4. 更新後驗證

    更新後列舉節點、測試裝置間連線、確認 policy 生效。

不跳版：不要從很舊的版本直接跳到最新，中間可能有多個不相容變更。照官方建議逐步升。

管理常見卡關

  1. 指令找不到或用法變了

    Headscale 指令隨版本演進（例如 namespace → user、acl → policy）。先看你的版本對應文件，別照舊教學硬打。

  2. 裝置連不上 DERP

    確認 DERP 清單可達、防火牆有放行；可先看 log 找中繼失敗的線索。

  3. policy 改了沒生效

    確認 policy 有正確匯入／儲存，並重跑相關驗證；部分變更要等節點重新同步。

  4. 更新後節點離線

    多半是設定或相容性變更，先看 release notes，再檢查 log 與節點狀態。

管理常見問題

一般使用者能動這些設定嗎？
不能。policy、DERP、使用者、版本更新都是管理員層級，一般使用者只管自己裝置連不連得上。
namespace 和 user 是同一個東西嗎？
概念相同，都是裝置分群。早期叫 namespace，新版本更名為 user，指令也跟著改，操作前看版本文件。
一定要自架 DERP 嗎？
不一定。多數情況用內建或外部 DERP 就夠；對掌控與隱私有更高要求才自架。
更新會讓裝置斷線嗎？
更新期間控制層會短暫中斷，已建立的點對點連線可能受影響。選離峰時段並先備份。
資料庫要單獨備份嗎？
要。使用者、節點、金鑰都存資料庫，單獨備份 config 是不夠的，兩者都要。
