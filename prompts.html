WoowTech · Headscale CLI/API 提示詞庫

用一句話，指揮你的網段

透過 headscale CLI/API，把下面這些自然語言提示詞交給 AI agent，讓它幫你管 user、preauth key、節點、ACL、路由、DNS 與備份。每一條都能複製，改成你家的說法就能用。

這本是什麼

Headscale 用 headscale 命令列管理控制層：users、preauthkeys、nodes、policy、routes、dns 等子命令。把這些包成 agent 工具後，你就能用自然語言操作。這本是「你要對 agent 說的話」的範本庫。

前提：需要 agent 能連到 Headscale（通常是執行 headscale 命令的環境）。敏感值（key、node id）用佔位符，別貼真實值。

怎麼用這些提示詞

複製 → 貼進 agent → 把佔位詞換成真實說法 → 送出。關鍵是講清楚「範圍」與「要做什麼」。

安全習慣：任何「刪除、撤銷、改 ACL」類動作，都先要求 agent 回報「將影響 N 個項目」讓你確認再執行。

user 與 preauth key

建立 user
用 headscale users create 幫我建立一個 user，名稱叫「family」，回傳建立結果。
產生 preauth key
幫 user「family」產生一個 preauth key，有效期 7 天、不可重複使用，回傳 key（用完提醒我撤銷）。
列出所有 user
用 headscale users list 列出所有 user 與建立時間。
盤點未使用的 key
列出所有 preauth key，標出還沒被使用、快到期或已過期的，建議我哪些該撤銷。
撤銷 key
把某個 preauth key 撤銷（先列出來讓我確認是哪一個，再執行）。
刪除 user
列出某個 user 名下的節點，確認沒有在用之後，再把它刪除（先回報影響範圍）。

節點管理

列出節點
用 headscale nodes list 列出所有節點：名稱、IP、狀態、是否過期。
找離線節點
找出最近 7 天沒上線的節點，列出來讓我決定要不要過期處理。
重新命名節點
把某個節點重新命名成更好記的名字（先列出現有名稱讓我確認）。
過期節點
把某個不再使用的節點標記為過期，讓它離開網段（先確認節點資訊）。
節點健康盤點
盤點所有節點的狀態與 IP，標出有問題的（離線、過期、IP 異常）。

ACL 與路由

檢視 ACL
讀取目前的 policy 檔，幫我白話解釋：現在哪些 user/群組能互連、哪些被擋。
加一條放行規則
在 policy 裡加一條 ACL：允許 user「family」的所有節點互相連線（先給我看修改前的 diff 確認）。
ACL 最小化稽核
檢查目前 ACL，找出「開太寬」的規則（例如 * 全放行），建議怎麼收緊。
列出路由
用 headscale routes list 列出所有 subnet route 與 exit node，標出還沒啟用的。
啟用路由
把某條 subnet route 啟用（先列出來讓我確認是哪一條）。

DNS 與備份

檢查 MagicDNS
確認 MagicDNS 是否有啟用，列出目前的 DNS 相關設定。
備份 policy 與金鑰
把目前的 policy 檔與關鍵設定備份一份（回傳內容讓我存檔，別貼敏感值）。
還原演練
寫一份 Headscale 災難還原步驟：假設控制層掛了，怎麼從備份重建 user、節點與 policy。

排錯與維運

健康檢查
做一次 Headscale 健康檢查：控制層狀態、版本、節點數、離線節點，逐項回報。
檢查版本
回報目前 Headscale 版本，並查官方是否有更新（若有，列出 release notes 重點）。
排錯節點連不上
某節點連不上控制層，幫我列排查清單：client 狀態、網路、控制層連線、key 是否有效。
DERP 檢查
確認 DERP 設定與中繼是否正常，節點直連失敗時能否走中繼。

常見問題

提示詞怎麼改才不會誤動網段？
永遠加「範圍」與「先回報、再執行」。例如「先列出會影響的項目，等我確認再執行」。
敏感值怎麼處理？
preauth key、node id 用佔位符，別在對話貼真實值；需要貼時先遮罩。
找不到某個命令？
headscale --help 或官方文件查子命令；不同版本略有差異，先讓 agent 查文件。
能讓 agent 直接刪節點/user 嗎？
建議先「過期／停用」而非「刪除」，並要求先回報影響範圍。
