第 9 章

DNS 與 MagicDNS

用裝置名稱互相連線，而不是記 IP。讀完這章，你會了解 MagicDNS 怎麼把節點名稱解析成網段內 IP，以及如何設定自訂 DNS 與 split DNS。

記名字比記 IP 好用

網段裡裝置一多，記 IP 很不切實際。MagicDNS 讓你能用裝置名稱（如 nas、客廳主機）直接互連，跟打 IP 一樣，但好記得多。

本章任務：了解 MagicDNS 怎麼運作、怎麼用名稱互連，以及自訂 DNS 的用途。

MagicDNS 是什麼

MagicDNS 是控制層提供的「名稱解析」服務：它給每個節點一個好記的名稱，並把名稱解析成網段內的 IP。你 ping nas 就等於 ping 那台裝置。

概念說明
節點名稱每台裝置在網段裡的 hostname
MagicDNS把名稱解析成 tailscale IP 的機制
split DNS只把特定網域交給指定 DNS 伺服器解析
名稱要在控制層可見：節點名稱由 client 端設定，控制層記錄並供 MagicDNS 解析。

五步用起名稱互連

  1. 確認 MagicDNS 有啟用

    在控制層的 DNS 設定確認 MagicDNS 開啟（Headscale 相關設定）。

  2. 為裝置設好名稱

    每台裝置用清楚的 hostname（如 nas、客廳），別用難記的預設名。

  3. 用名稱互連

    在另一台節點 ping nas 或 ssh 客廳，看名稱解析是否正確。

  4. 需要時設 split DNS

    把公司內網或特定網域的解析導到指定 DNS 伺服器，其餘走預設。

  5. 確認不衝突

    節點名稱不要跟內網既有 hostname 衝突，避免解析混淆。

自訂 DNS 與 split DNS

  • 自訂 DNS：指定網段內裝置使用的 DNS 伺服器（例如內網的 Pi-hole、AdGuard）。
  • split DNS：只把「特定網域」交給指定伺服器解析，例如公司內網的 internal.example.com，其餘流量不受影響。
  • 用途：廣告阻擋、內網服務名稱解析、隔離不同網域的解析策略。
改 DNS 影響所有節點：DNS 設定是控制層級的，改動會影響整個網段。先確認再改，並留下備份。

DNS 常見卡關

  1. 名稱解析不到

    確認 MagicDNS 啟用、節點名稱無衝突、對方節點在線。

  2. 名稱解析到錯的裝置

    節點名稱重複或舊名稱未更新，檢查並重新命名。

  3. 自訂 DNS 沒生效

    確認設定已套用並重新整理節點 DNS；部分變更需節點重新連線。

  4. 內網服務名稱衝突

    節點名稱跟內網 hostname 撞名，改用不衝突的名稱或調整 split DNS。

DNS 常見問題

MagicDNS 是必須的嗎？
不是。可以只用 IP 互連。但名稱互連好用很多，建議開。
能用中文節點名稱嗎？
依 client 與控制層支援而定，多數環境可用，但為了相容性，建議用英數 hostname 較保險。
split DNS 和一般 DNS 差在哪？
一般 DNS 全用同一台；split DNS 只把特定網域分流到指定伺服器，其餘照舊。
能接 Pi-hole 擋廣告嗎？
能。把網段的自訂 DNS 指到 Pi-hole，所有節點的解析就都經過它擋廣告。
改了名稱舊的還會通嗎？
改名稱後舊名稱通常失效，用新名稱連；部分快取可能要稍等才更新。
