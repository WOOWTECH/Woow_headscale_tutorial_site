第 11 章

安全與最小暴露

從控制層入口、preauth key、ACL 到節點盤點，做一次系統性的安全檢查。讀完這章，你會知道哪些習慣能守住私有網段，哪些「方便」其實是過度暴露，並學會把暴露範圍縮到最小。

私有網段最怕鑰匙外流

Headscale 的整張網，安全性繫於幾樣東西：控制層入口、preauth key、ACL 規則。任何一樣沒守住，你的「私有」網段就可能被外人溜進來。安全不是設定一次就好，而是幾個習慣長期守住。

本章任務：逐項檢查入口、金鑰、ACL 與節點，把不必要的暴露收起來。全程只做「收緊」，不刪資料。

安全的三道防線

防線守什麼你的責任
控制層入口誰能接觸管理介面／API不對外公開、只留管理員
preauth key誰能把裝置加進網段當最高機密、用完就撤銷
ACL（policy）裝置之間誰能連誰預設全拒、只放行必要互連
最小暴露原則：任何東西預設不開；要開，只開到「剛好夠用」，並保留撤銷的能力。

六步安全檢查清單

  1. 檢查控制層不外露

    確認管理介面／API 只在內網或受控入口可達，沒有對整個網際網路開放。

  2. 盤點 preauth key

    用 headscale preauthkeys list 看還有哪些未使用的金鑰，用不到的立刻撤銷。

  3. 檢查 ACL 是否最小化

    用 headscale policy get 檢視規則，確認不是「全放行」，只留必要互連（第 7 章）。

  4. 盤點節點

    用 headscale nodes list 看有哪些裝置，認不出來的節點先停用再查。

  5. 檢查金鑰與帳號

    管理員帳號別到處給；API key（若有用）也要定期輪替。

  6. 確認備份在跑

    config、policy、資料庫都有定期備份（第 10 章），並做過還原演練。

遇到可疑節點：看到不認得的裝置或金鑰，先撤銷金鑰、停用節點，再追查來源，不要拖。

preauth key 的管理

preauth key 是讓裝置加入網段的「預授權鑰匙」。拿到它的人，就能把裝置掛進你的網段。管理原則是：

  • 一機一鑰、用完即撤：不要一把鑰匙反覆用，也不要共用。
  • 不要貼在公開處：金鑰別寫進群組聊天、別 commit 進 repo。
  • 定期盤點：撤銷所有「已經用過」或「已經不需要」的金鑰。
金鑰外流的補救：立刻撤銷該金鑰，並盤點是否有不明節點因此加入，必要時收緊 ACL。

ACL 最小化

ACL（policy）決定「誰能連誰、能連哪些 port」。最安全的心態是「預設全拒，白名單放行」：

做法說明
預設全拒沒有明寫放行的，一律不通
只放行必要互連例如「手機能連家裡的 HA，其他都不行」
依使用者分區家人裝置與工作裝置分開，互不越界
改了要驗證：ACL 改完，實際從裝置測一次「該通的通、不該通的不通」，不要只看設定以為對了。

節點盤點

定期列舉節點，就像盤點「誰在家裡網段上」。重點：

  • 每個節點都要認得出來（名字、裝置、用途）。
  • 不認得的節點：先停用，再追查它是誰加的、用哪把鑰匙。
  • 久未上線的裝置：確認是否還需要，不需要就移除。
節點名字別洩露敏感資訊：命名用可辨識但不洩密的說法，別把完整人名、地址、序號放進節點名。

安全相關卡關

  1. 懷疑金鑰外流

    立刻撤銷該金鑰，盤點節點與近期加入記錄，必要時收緊 ACL 並通知使用者。

  2. 發現不明節點

    停用節點、撤銷可疑金鑰，再查它是從哪加入的。

  3. ACL 放太寬想收緊

    先列出現有互連需求，逐條放行，其餘全拒；改完實際驗證。

  4. 不確定某個東西該不該開

    預設「不開」。拿不準就先關，需要時再開。

安全常見問題

控制層被掃描到會怎樣？
管理介面／API 若對外暴露，攻擊者可能嘗試登入或列舉。這就是為什麼控制層要留在內網、不對外公開。
preauth key 可以重複使用嗎？
可以，但強烈不建議。一機一鑰、用完即撤最安全；共用一把會讓撤銷與追蹤變難。
ACL 全放行有什麼風險？
等於網上所有裝置都能互連所有 port。任何一個裝置被入侵，整張網都可能淪陷。務必最小化。
多久盤點一次比較好？
建議每月一次快速盤點（金鑰、節點、ACL）；有異常（不明節點、金鑰外流疑慮）時立刻檢查。
管理員帳號需要特別保護嗎？
要。管理員能改 policy、刪節點。用強密碼、別到處給，API key 定期輪替。
