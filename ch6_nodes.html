第 6 章

節點管理

學會查看、命名、過期與移除網段裡的節點。讀完這章，你會知道每個裝置在 Headscale 裡的狀態、何時該過期、何時該移除，把網段顧得清清楚楚。

節點是網段的成員名單

每台加入的裝置，在 Headscale 裡就是一個「節點（node）」。時間一久，你可能不記得有哪些裝置在網上、哪些該退休。節點管理讓你看清成員名單、控制誰還在、誰該移除。

本章任務：列出節點、看懂狀態、幫節點命名、讓不再用的節點過期或移除。移除節點只影響那台裝置的連線，不影響其他成員。
移除要謹慎：移除節點後，那台裝置就再也連不進網段，要重新加入得用新的 preauth key（第 4、5 章）。動手前確認它是真的不要了。

節點、狀態與識別

Headscale 用幾個欄位描述每個節點：

欄位說明
ID節點的唯一編號（用於多數 CLI 命令）
Name裝置名稱，可自行重新命名以便辨識
IP address節點在網段內的私有 IP
Last seen上次上線時間，判斷裝置是否活躍
Expired是否已過期（過期後裝置需重新驗證才能連）
ID 是敏感值：節點 ID、IP 在分享畫面或求助時記得遮罩，不要整段貼出去。

六步完成一次節點管理

  1. 列出所有節點

    用 headscale nodes list 查看網段裡所有節點，含 ID、名稱、IP 與狀態。

  2. 認出每台裝置

    對照名稱與「上次上線」，認出哪台是哪台。名稱太像的就先命名（下一步）。

  3. 幫節點改名

    用 headscale nodes rename --identifier <ID> 新名稱 把名稱改成好認的，例如「客廳電視」。

  4. 看狀態與到期

    確認哪些節點已過期（Expired）、哪些還在線。過期代表裝置需要重新驗證。

  5. 過期不再用的節點

    用 headscale nodes expire --identifier <ID> 讓某個節點過期，它會失去連線、需要重新登入。

  6. 移除確定不要的節點

    用 headscale nodes delete --identifier <ID> 移除。移除前再確認一次。

命令版本差異：Headscale CLI 的參數（--identifier 或直接用 ID）會隨版本微調，以你環境的 headscale nodes --help 為準。

狀態與到期怎麼看

節點主要有「在線」「離線」「已過期」幾種樣貌。理解它們，你就知道何時該處理：

狀態代表什麼該做什麼
在線（最近上線）裝置正常運作、剛回報過不用動
離線一段時間裝置關機或暫時離線先觀察，不必急著移除
已過期（Expired）裝置需重新驗證才能連讓裝置重新登入，或直接移除
過期不是壞事：過期是一種安全機制，讓久久沒用、可能失竊的裝置自動斷線，直到重新驗證。

過期與重新驗證

當你「過期」一個節點，那台裝置會被踢出網段。要讓它回來，得在裝置端重新登入驗證（第 5 章）。這適合：

  • 懷疑裝置失竊或不再信任。
  • 暫時停用某台裝置，之後再恢復。
  • 強制某台裝置重新走一次驗證流程。
過期 ≠ 移除：過期只是讓它斷線、可重新驗證；移除是把節點從名單刪掉，要重新加入得用新的 preauth key。

節點常見卡關

  1. 節點一直離線

    先確認那台裝置有開機、tailscale client 有在跑。裝置端正常再回頭查控制層（第 12 章）。

  2. 改名後沒生效

    名稱同步需要一點時間；重新整理列表，或用 nodes list 再看一次。

  3. 誤刪了節點

    重新加入需新的 preauth key。養成移除前雙重確認的習慣。

  4. 命令找不到或參數不同

    Headscale 版本不同參數會變。先 headscale nodes --help 看當下支援的寫法。

節點常見問題

一個節點就是一台裝置嗎？
通常是一台裝置一個節點。同一台裝置重裝 client 可能產生新節點，舊的記得清掉。
節點 IP 會變嗎？
網段內 IP 通常穩定，但可能因重新加入而改變。用名稱識別比記 IP 可靠。
過期後裝置自己會恢復嗎？
不會自動恢復，要在裝置端重新登入驗證，才會回到網段。
移除節點會影響別人嗎？
不會。移除只影響那台裝置，其他節點照常互連。
可以一次移除很多節點嗎？
可以逐一移除；沒有把握時先「過期」而非「移除」，保留恢復空間。
