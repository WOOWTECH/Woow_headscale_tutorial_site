Chapter 3

First open and sign-in

Get to know how Headscale is managed — it is driven mainly by the command line (CLI) and the API, and only some environments have a Web UI. By the end of this chapter, you'll have checked the version and status, you'll recognize the basic commands, and you'll know why the control server must not be exposed.

The control server is not what you expect

The services you set up earlier (photo album, cloud drive) all came with a nice graphical interface. Headscale is different: it is a back-end service, and most management work goes through the command line (CLI) and the API. Get that clear first, and you will not spend your time hunting for a "settings button" that is not there.

Chapter task: Open a terminal on the control server, check the version and status, and get to know a few basic commands. Everything here is read-only; you create nothing.

Adjust your expectations: Think of Headscale as a server you type commands into, not an app you click around in. Once the commands are familiar it goes quickly.

Five steps to check version and status

  1. Open the add-on terminal

    On the Headscale add-on page in Home Assistant, find the "Terminal" entry point (or connect to the host over SSH) and get to a command line.

  2. Check the version

    Type headscale version. It shows the Headscale version number you are running.

  3. See which users exist

    Type headscale users list to list the current users (namespaces, the legacy name). A fresh install may only have the default entry.

  4. See which nodes exist

    Type headscale nodes list to list the nodes that have joined. Right after an install this is usually still empty.

  5. Read the log to confirm it is running

    Go back to the add-on's "Log" tab and confirm there are no repeating errors and that the service keeps running.

Run commands in the right place: The headscale command only exists inside the add-on container or in the headscale runtime environment on the host. In the wrong place you get "command not found".

Use --help: If you are not sure how a command works, type headscale <subcommand> --help and it prints an explanation. Get into the habit of reading the help first.

Why the control server must not be exposed

The control server is the brain of the whole tailnet: the node list, the ACL and the keys all live there. Once an outsider can reach it, your private tailnet has effectively been taken over. So:

  • The management interfaces (CLI / API / Web UI) are for admins only and are never exposed to the public internet.
  • What a client connects to is the endpoint used for joining, not the whole management interface exposed to the public internet.
  • When you do need outside access, run it through an encrypted tunnel such as Cloudflare Tunnel instead of opening a port directly.
Hard stop: Do not publish the Headscale management interface straight to the internet just to make remote access convenient. Remote management goes through a secure channel + least privilege.

Common first-open pitfalls

  1. You cannot find the terminal

    Different add-ons put the terminal in different places. Look for "Terminal" on the add-on page, or ask your admin how to get to the CLI.

  2. Typing headscale says command not found

    You are not in the right runtime environment. Make sure you opened the add-on container's terminal, or that headscale is installed on the host.

  3. The command reports insufficient permissions

    Some operations need higher privileges. Run them as the right user, or ask an admin to handle it.

  4. There is no Web UI and it feels unfamiliar

    Headscale is CLI- and API-first; a Web UI is optional. Get comfortable with the CLI — every later chapter uses commands.

First open FAQ

Why doesn't Headscale have a nice interface?
It is the control server back end. Its job is managing nodes and the policy, not day-to-day use. Everyday browsing and device-to-device connections run through the client side (Tailscale), so you do not need to watch the control server all day.
Do I have to be able to type commands?
For admin actions (creating users, issuing keys) yes. For everyday use (devices connecting to each other) you barely touch the control server. There are not many commands, and you can type them as written.
What is a Web UI?
Some deployments install a separate graphical interface such as headscale-ui, which makes it easier to look at status. Full management is still done through the CLI and API.
Does the version that headscale version shows matter?
Yes. When you troubleshoot or check what a feature does, you have to match the version, and the client side has to be compatible as well. A version mismatch is sometimes the source of the problem.
Can I open the control server up to my family?
The control server is for admins only. Family members just join the tailnet with their devices (Chapter 5); they do not need to touch the control server.
