Chapter 6

Node management

Learn how to list, rename, expire and remove the nodes in your tailnet. By the end of this chapter, you'll know the status of every device in Headscale, when to expire a node, when to remove one, and how to keep the tailnet in good order.

Nodes are the tailnet's roster

Every device that joins becomes a "node" in Headscale. After a while you may not remember which devices are still on the network and which ones should be retired. Node management lets you see the roster clearly, control who is still on it, and decide who should be removed.

Chapter task: list your nodes, read their status, give them names, and expire or remove the ones you no longer use. Removing a node only affects that device's connection; the other members are unaffected.
Remove with care: once a node is removed, that device can no longer connect to the tailnet, and rejoining takes a new preauth key (Chapters 4 and 5). Make sure you really are done with it before you act.

Nodes, status and identity

Headscale describes each node with a few fields:

FieldWhat it means
IDThe node's unique number (used by most CLI commands)
NameThe device name. You can rename it yourself to make it easier to recognize
IP addressThe node's private IP address inside the tailnet
Last seenWhen the device was last online, so you can tell whether it is still active
ExpiredWhether it has expired (after expiry the device has to reauthenticate before it can connect)
Node IDs are sensitive: when you share a screen or ask for help, redact the node ID and the IP address instead of pasting the whole block.

Six steps through one round of node management

  1. List every node

    Run headscale nodes list to see every node in the tailnet, with its ID, name, IP address and status.

  2. Identify each device

    Compare the name against "Last seen" to tell the devices apart. If two names look too similar, rename them first (the next step).

  3. Rename a node

    Run headscale nodes rename --identifier <ID> <new-name> to change the name to something you will recognize, for example "living-room-tv".

  4. Check status and expiry

    Confirm which nodes are Expired and which are still online. Expired means the device has to reauthenticate.

  5. Expire the nodes you no longer use

    Run headscale nodes expire --identifier <ID> to expire a node. It loses its connection and has to log in again.

  6. Remove the nodes you are sure you no longer want

    Run headscale nodes delete --identifier <ID> to remove one. Check once more before you do.

Commands vary by version: the Headscale CLI flags (--identifier, or the ID on its own) shift slightly from version to version. Go by headscale nodes --help in your own environment.

How to read status and expiry

A node shows up in a few main states: "online", "offline" and "expired". Once you understand them, you know when to step in:

StatusWhat it meansWhat to do
Online (seen recently)The device is working normally and checked in a moment agoNothing to do
Offline for a whileThe device is powered off or temporarily offlineWatch it for now; there is no rush to remove it
ExpiredThe device has to reauthenticate before it can connectHave the device log in again, or just remove it
Expiry is not a failure: expiry is a safety mechanism. A device that has gone unused for a long time, or that may have been stolen, is disconnected automatically until it reauthenticates.

Expiry and reauthentication

When you "expire" a node, that device is kicked out of the tailnet. To bring it back, log in and authenticate again on the device itself (Chapter 5). This fits when:

  • You suspect the device was stolen, or you no longer trust it.
  • You want to disable a device for now and bring it back later.
  • You want to force a device through the authentication flow one more time.
Expire ≠ remove: expiring only disconnects it and lets it reauthenticate; removing deletes the node from the roster, and rejoining takes a new preauth key.

Common node pitfalls

  1. A node stays offline

    First check that the device is powered on and the Tailscale client is running. Once the device side looks fine, go back and check the control server (Chapter 12).

  2. The new name has not taken effect

    Names take a moment to sync. Refresh the list, or run nodes list and look again.

  3. You deleted a node by mistake

    Rejoining needs a new preauth key. Get into the habit of double-checking before you remove anything.

  4. The command is missing, or the flags are different

    Flags change between Headscale versions. Run headscale nodes --help first to see the form your version supports.

Nodes FAQ

Is one node the same as one device?
Usually one device is one node. Reinstalling the client on the same device can create a new node, so remember to clear the old one out.
Does a node's IP address change?
Tailnet IP addresses are usually stable, but they can change when a device rejoins. Identifying a device by name is more reliable than remembering its IP address.
Does an expired device come back on its own?
It does not recover automatically. You have to log in and authenticate again on the device before it returns to the tailnet.
Does removing a node affect anyone else?
No. Removing only affects that device; the other nodes keep talking to each other as before.
Can I remove many nodes at once?
You can remove them one at a time. When you are not sure, "expire" rather than "remove", so you leave yourself room to recover.
