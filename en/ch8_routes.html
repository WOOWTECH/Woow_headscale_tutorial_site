Chapter 8

Routes and exit nodes

Use a subnet router to bring a whole local network into your private tailnet, and an exit node to push traffic out through one particular device. By the end of this chapter, you'll be able to reach your whole home network safely from any network outside the house — the NAS, the printer and everything else on it.

More than devices: bring a whole subnet home

The earlier chapters connected "a single device" at a time. But a home usually has a whole local network behind it (NAS, printer, cameras, router), and those devices cannot always run Tailscale. With a subnet router, you nominate one device as the "bridge" and bring that entire local network into your private tailnet.

Chapter task: Learn the difference between a subnet router and an exit node, and learn how to advertise and approve routes. Route settings affect the whole tailnet, so confirm the blast radius before you touch anything.

Subnet router and exit node

ConceptWhat it doesTypical use
subnet routerAttaches one local subnet (192.168.1.0/24, for example) to the tailnet so other nodes can reach the devices on itReaching the NAS or the printer at home while you are out
exit nodeSends "all outbound traffic" from other nodes out through this one machineBrowsing from a cafe with your home IP address, encrypting outbound connections
Not the same thing: a subnet router "brings the local network in"; an exit node "sends traffic out". Do not mix the two up.

Six steps to set up a subnet router

  1. Pick a device that is always on to be the bridge

    Choose a device at home that stays powered on all the time (your Home Assistant host or a NAS, for example) to act as the subnet router.

  2. Advertise the subnet you want to forward

    On that device, run tailscale up --advertise-routes=192.168.1.0/24 (replace it with your own subnet).

  3. Approve the route on the control server

    Use Headscale's route command to list this subnet route and approve it. Until you do, it will not take effect.

  4. Test the local network from another device

    From another node, ping a device on the local network (ping 192.168.1.10, for example) and confirm the traffic gets through.

  5. Set up an exit node if you need one

    Add --advertise-exit-node on the bridge device, then tell the other nodes to use it as their exit.

  6. Take inventory and keep it minimal

    Advertise only the subnets you genuinely need. Do not open up a whole large subnet.

Minimal exposure: the wider the subnet you advertise, the more things can be reached. Open only the small range you need (the subnet the NAS sits on, for example), not the entire local network.

Exit node

An exit node makes your device send "all outbound traffic" out through one particular node. That is useful when you are "away from home and want to browse with your home IP address", or when you want to "encrypt outbound connections on public Wi-Fi".

  • Once it is set up, every other node has to "select it manually" as its exit node before anything changes.
  • Note that all traffic goes through it, so the bandwidth and the location of that machine affect your speed.
  • If you use it as a way to "tunnel back home", be sure to follow the local terms of service.
An exit node is not a magic proxy: it only moves your exit point somewhere else. It does not change the basic rules of content encryption or privacy.

Common routing pitfalls

  1. The route is advertised but the local network is unreachable

    Check that the control server has "approved" the route (advertising is not approving), and check that you typed the subnet correctly.

  2. You can ping the router but not the local network behind it

    Check whether IP forwarding is turned on for the router machine. The setting differs from one OS to another.

  3. The exit node has no effect

    Every other node has to "select it manually" as its exit node. Confirm that this machine advertises itself as an exit node and that the control server has accepted it.

  4. Devices on the local network never answer

    The firewall or the default gateway on those devices may be blocking traffic coming from the tailnet. Check the routing on the local network.

Routing FAQ

Does the subnet router machine have to stay powered on?
Yes. It is the bridge; switch it off and the link goes down. Pick a stable device that is always on.
Can I advertise more than one subnet at a time?
Yes, separate the subnets in --advertise-routes with commas. But keep it minimal and open only what you need.
Is an exit node the same as a VPN?
The effect is similar, in that it "moves your exit point somewhere else", but it is one part of the Tailscale/Headscale mesh, not a traditional centralized VPN.
Is advertising a route a security risk?
Yes, it exposes that subnet to every other node in the tailnet. Always pair it with an ACL that limits who can connect, and advertise the smallest subnet that works.
Can a phone be a subnet router?
In theory yes, but it is not a good idea (phones sleep often, and IP forwarding support is limited). A device that is always on is more reliable.
