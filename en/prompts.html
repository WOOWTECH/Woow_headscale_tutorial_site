Command your tailnet in one sentence

Hand the natural-language prompts below to an AI agent and let it manage users, preauth keys, nodes, ACLs, routes, DNS and backups for you through the headscale CLI/API. Copy any of them, reword them to match your own setup, and they are ready to use.

What this is

You manage the Headscale control server from the headscale command line, with subcommands such as users, preauthkeys, nodes, policy, routes and dns. Wrap those as agent tools and you can drive them in natural language. This handbook is the template library for "what you say to the agent".

Prerequisite: the agent has to be able to reach Headscale (usually the environment where the headscale command runs). Use placeholders for sensitive values (keys, node IDs) instead of pasting the real ones.

How to use these prompts

Copy → paste into the agent → replace the placeholder words with your own wording → send. What matters is being clear about the scope and the action.

Safe habit: for any "delete, revoke, change the ACL" action, make the agent report "this will affect N items" and wait for your confirmation before it runs.

Users and preauth keys

Create a user
Use headscale users create to create a user named "family", and report the result. Answer in English.
Generate a preauth key
Generate a preauth key for the user "family", valid for 7 days and not reusable, and return the key (remind me to revoke it once it has been used). Answer in English.
List all users
Use headscale users list to list every user and its creation time. Answer in English.
Inventory unused keys
List every preauth key, flag the ones that are still unused, expiring soon or already expired, and tell me which ones I should revoke. Answer in English.
Revoke a key
Revoke one preauth key (list them first so I can confirm which one, then run it). Answer in English.
Delete a user
List the nodes that belong to one user, confirm none of them is still in use, then delete the user (report the blast radius first). Answer in English.

Node management

List nodes
Use headscale nodes list to list every node: name, IP address, status, whether it has expired. Answer in English.
Find offline nodes
Find the nodes that have not come online in the last 7 days and list them, so I can decide whether to expire them. Answer in English.
Rename a node
Rename one node to something easier to remember (list the current names first so I can confirm). Answer in English.
Expire a node
Mark one node that is no longer in use as expired so it leaves the tailnet (confirm the node details first). Answer in English.
Node health inventory
Take inventory of every node's status and IP address, and flag the ones with a problem (offline, expired, unexpected IP address). Answer in English.

ACL and routes

Review the ACL
Read the current policy file and explain it to me in plain language: which users and groups can connect to each other right now, and which are blocked. Answer in English.
Add one allow rule
Add one ACL rule to the policy: allow every node of the user "family" to connect to the others (show me the diff before the change so I can confirm). Answer in English.
ACL minimization audit
Check the current ACL, find the rules that are too wide (a * that allows everything, for example), and suggest how to tighten them. Answer in English.
List routes
Use headscale routes list to list every subnet route and exit node, and flag the ones that are not approved yet. Answer in English.
Approve a route
Approve one subnet route (list them first so I can confirm which one). Answer in English.

DNS and backups

Check MagicDNS
Confirm whether MagicDNS is enabled, and list the current DNS settings. Answer in English.
Back up policy and keys
Back up the current policy file and the critical settings (return the contents so I can save them, and do not paste sensitive values). Answer in English.
Restore drill
Write a Headscale disaster recovery procedure: assume the control server is down, and describe how to rebuild users, nodes and the policy from a backup. Answer in English.

Troubleshooting and operations

Health check
Run a Headscale health check: control server status, version, node count, offline nodes. Report each item in turn. Answer in English.
Check the version
Report the current Headscale version and check whether an official update exists (if there is one, list the key points from the release notes). Answer in English.
Troubleshoot a node that cannot connect
A node cannot reach the control server. Give me a troubleshooting checklist: client status, network, the connection to the control server, whether the key is still valid. Answer in English.
DERP check
Confirm that the DERP settings and relays are healthy, and that traffic can fall back to a DERP relay when nodes cannot connect directly. Answer in English.

FAQ

How do I edit a prompt so it does not disturb the tailnet by accident?
Always add the scope and a "report first, then run" step. For example: "list the items this will affect and wait for my confirmation before you run it".
What do I do about sensitive values?
Use placeholders for preauth keys and node IDs, and never paste the real values into the conversation; if you have to paste one, redact it first.
Cannot find a command?
Look the subcommand up with headscale --help or in the official docs; versions differ slightly, so have the agent check the docs first.
Can I let the agent delete a node or a user directly?
Prefer to expire or disable rather than delete, and require it to report the blast radius first.
