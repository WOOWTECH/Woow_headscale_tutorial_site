Chapter 4

Create a user and a preauth key

Create your first user in Headscale, then generate the preauth key that lets a device join the tailnet. By the end of this chapter, you'll know how users and keys relate, and how to safely hand a new device a "key you can revoke".

No user, no device

Headscale uses a "user" to own nodes: every device that joins the tailnet has to sit under some user. And the key that lets a device "join by itself" is the preauth key. Creating a user and issuing a key is what makes a second and a third device possible.

Chapter task: create a user, generate a preauth key, and get to know the key's lifecycle and security. These actions change the state of the control server, so be clear about what you need them for before you start.

How users and preauth keys relate

ConceptWhat it means
userThe unit a node belongs to. One user can have several devices
preauth keyA single-use (or reusable) key that lets a device skip the interactive login and join a given user directly
nodeOnce it has joined, each device is a node

The flow is: create the user → generate a preauth key for that user → hand the key to the device → the device joins with it → revoke the key once it has been used.

In one line: a user is "ownership", a preauth key is "the ticket at the door". The ticket is bound to one user, and you tear it up once it has been used.

Six steps to create a user and a preauth key

  1. Get into the Headscale admin environment

    In the add-on's terminal or on the host, confirm that you can run the headscale command (Chapter 3).

  2. Create the user

    Run headscale users create <name> — for example headscale users create family — to create a user called family.

  3. Check that the user was created

    Run headscale users list; the user you just created should appear in the list.

  4. Generate the preauth key

    Run headscale preauthkeys create --user family. The command returns a key that looks something like headscale-xxxxx....

  5. Add an expiry and reusability if you need them

    Add --expiration 24h to make it valid for 24 hours, or --reusable to let it be used more than once (single-use is the default).

  6. Record the key and store it safely

    Write the returned key down in full (use a password manager); do not paste it into a public chat or a notes app. You will need it in Chapter 5.

The key is shown once: a preauth key is usually shown in full only when you create it, and after that the list may show only the prefix. Save it the moment you create it.

Key lifecycle and management

ActionCommand (example)When
List one user's keysheadscale preauthkeys list --user familyTo take inventory of which keys are out there
Revoke / expireheadscale preauthkeys expire --user family <key>After the device has joined, or when a key leaks
Delete a userheadscale users destroy <name>After you have dealt with every node under that user
A key is a key: anyone who gets hold of a preauth key can join a device to your tailnet. Treat it as a top secret; revoke it immediately once it has been used, or if it went to the wrong person.

How to organize users

How you split users up decides how easy management and the ACL will be later on. Households and small teams usually take one of two approaches:

ApproachBest forTrade-offs
One shared user for the whole householdSmall households where everyone trusts each otherSimple, but hard to give different people different permissions
One user per personWhen you need to separate permissions and manage people individuallyMore work, but the ACL can control access precisely (Chapter 7)
Start simple: at first, use a single user to get the whole flow working. Once you have more devices and need to separate permissions, split it into one user per person.

Common setup pitfalls

  1. users create fails

    The name may already exist, or you may not have admin rights. Check with headscale users list.

  2. preauthkeys create returns an error

    Confirm that the user named by --user already exists; a misspelled user name will fail.

  3. You closed the window before saving the key

    The key will usually not be shown in full again. The safest move is to revoke the old one and generate a new one.

  4. The device cannot join with the key

    Check whether the key has expired, whether it is bound to the right user, and whether it has already been used up (a single-use key).

Setup FAQ

How many devices can one user have?
There is no hard limit. One household device or a whole set of family devices can sit under the same user, or you can split them across several users.
What is the difference between a preauth key and logging in with a username and password?
A preauth key is the key that lets a device join with "no interaction", which suits automation and command-line situations; interactive login goes through browser authorization instead. Both are ways of authorizing a device to join.
How long can a key stay valid?
Use --expiration to set the validity period (24h, 1h, and so on). The default validity depends on your Headscale settings; for anything temporary, keep it short.
What does "--reusable" mean?
It lets the same key join several devices; leave it off and the default is "valid for one use only". You do not need it when you are issuing a one-off key to a single device.
What if a key leaks?
Revoke it immediately with headscale preauthkeys expire, then generate a new one. For nodes that already joined with that key, go to node management (Chapter 6) and decide whether to remove them.
