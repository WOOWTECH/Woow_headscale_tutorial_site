Chapter 1

Before you start: keep the VPN control server in your own home

First, get clear on what Headscale is, why you would self-host a VPN control server, and how it differs from official Tailscale. By the end of this chapter, you'll know what this WoowTech Headscale setup can do for you, and which security lines you must not cross.

Why self-host the control server

Tailscale lets you link devices scattered in different places into one private network, with no public port to open and no IP address to remember. But by default it hands the control logic for "who can reach whom, and which nodes exist" to the official coordination server (control plane).

Headscale is "a self-hosted Tailscale control server": the same connection experience, except that the control server runs in your own home. The node list, the ACL and the keys are all yours to decide, with no third party in the middle.

Chapter goal: not to teach you how to set up a server, but to make sure that before you start using it you understand where Headscale sits, how it relates to official Tailscale, and where the security boundaries are. The hands-on work starts with the install in Chapter 2.
To be clear: half of the "security" of a self-hosted control server is your own responsibility. A preauth key left lying around, or an ACL opened too wide, leaves your private network as good as nonexistent.

What Headscale is

Headscale is an open source, self-hosted implementation of the Tailscale coordination server. It is the brain that manages the whole tailnet, but the actual traffic still runs over encrypted peer-to-peer tunnels between the devices themselves (WireGuard).

ConceptWhat it means
Control planeThe server that manages nodes, ACLs, keys and DNS
Data planeThe actual encrypted connection between devices (WireGuard)
Tailscale clientThe client installed on a device, which connects to a control server (official or Headscale)
DERPThe relay server used when a peer-to-peer connection cannot be made
In one line: Tailscale's "coordination server" is run by Tailscale; Headscale is the open source, self-hosted version of that same coordination server, and you run it yourself.

What this WoowTech Headscale setup looks like

You'll be using the Headscale instance WoowTech runs inside a Home Assistant add-on. Paired with the Tailscale client, it links the household's devices into a private tailnet of your own.

  • Entry point: the control server itself, where you manage nodes and the policy (Chapter 3).
  • How you manage it: mainly the command line (CLI) and the API; some environments also have a Web UI (depending on the deployment).
  • Joining devices: point the Tailscale client on the device at this Headscale server and it joins (Chapter 5).
  • Cross-reference: see the sister site "Tailscale HA Add-on Guide" for the client-side steps.
Mental model: Headscale is the headquarters and the Tailscale client on each device is a branch store. Headquarters decides who can reach whom (the ACL), and the branch stores connect to one another directly over encrypted tunnels.

Security boundaries before you start

  • A preauth key is a key: anyone who gets hold of it can join a device to your tailnet, so treat it as a top secret and revoke it once it has been used.
  • Minimize the ACL: default deny; allow only the connections you actually need.
  • Keep the control server private: the admin interface is for admins only and is never exposed to the public internet.
  • Back up the policy and the keys: these are what you cannot lose if you ever have to rebuild the tailnet, so include them in your backups.
Hard stop: do not publish a preauth key, the admin interface or the whole ACL just because it is convenient. Anyone who needs to join gets exactly one "single-use, revocable" key.

Before you start FAQ

Are Headscale and Tailscale from the same company?
No. Tailscale is the official service; Headscale is a third-party open source project, a self-hosted implementation of the Tailscale coordination server. The two are compatible, and on the device side both use the Tailscale client.
Do I need to know how to set up a server?
Not as a user. WoowTech takes care of deployment and maintenance; this guide teaches you how to use this tailnet.
Does traffic between devices still go through the official servers?
No. The control server is your own Headscale, and data traffic runs as a direct, encrypted peer-to-peer connection between devices; traffic falls back to a DERP relay only when a direct connection cannot be made.
How is this different from an ordinary VPN?
A traditional VPN is usually a "central gateway"; Tailscale/Headscale is a "peer-to-peer mesh" in which devices connect to each other directly, which suits a private tailnet with many devices much better.
Can the Headscale server see my data?
The control server can see nodes and the policy (who is on the network, and who can reach whom), but the actual file traffic is a direct encrypted connection between devices, and the control server never handles it.
