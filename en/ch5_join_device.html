Chapter 5

Join your first device

Point one device's Tailscale client at your Headscale and use it to join the tailnet. By the end of this chapter, your first device will show up in the node list and your private tailnet is officially open.

A tailnet is not alive until a device joins

Chapter 4 created a user and a preauth key, but there is still no device in the tailnet. Here you join the first device and prove that the whole "control server → key → client" flow really works; every device after this one follows the same path.

Chapter task: install the Tailscale client on a device, point it at Headscale, join with a key, and confirm the node appears in the list.

How a device joins the tailnet

By default the Tailscale client on a device connects to the official servers; to reach your Headscale, you have to tell it "where the control server is". The way to do that is to run tailscale up with --login-server pointing at your Headscale URL.

StepWhat it means
Install the clientInstall Tailscale (the official client) on the device
Point it at the control servertailscale up --login-server <url>
AuthorizePaste the preauth key, or log in through the browser
VerifySee the node appear in Headscale
The key difference: with official Tailscale, tailscale up logs you straight into the official service; self-hosting just adds --login-server on top, and everything else feels the same.

Six steps to join your first device

  1. Install the Tailscale client on the device

    Go to the Tailscale website, download the client for your operating system, and install it (clients are available for Windows, macOS, Linux, iOS and Android).

  2. Have the preauth key ready

    Get the preauth key you generated in Chapter 4 and have not used yet.

  3. Point it at Headscale and log in

    In a terminal, run tailscale up --login-server <headscale-url> — for example tailscale up --login-server https://your-headscale.example.

  4. Authorize with the key

    Paste the preauth key when you are prompted, or log in through the browser authorization flow.

  5. Wait for the connection to come up

    The client connects to the control server and picks up its node identity; once tailscale up has finished, you are done.

  6. Verify back on Headscale

    Run headscale nodes list. Seeing the new node in the list means it joined successfully.

Get the URL right: --login-server takes your Headscale's public URL (including https). Get it wrong and you will reach the wrong control server, or the command will simply fail.

Run it as a service: on Linux you can run tailscale up and then leave the client running as a service (with systemd or whatever your distribution uses), so it connects automatically at boot.

Verify the device joined

  • Run tailscale status on the device; it should show that you are connected and the node address it was assigned.
  • Run headscale nodes list on Headscale and confirm that the new node, and the user it belongs to, are both right.
  • Once you add a second device, the two should be able to ping each other (Chapters 6 and 7 cover connectivity between nodes and the ACL).

Common join pitfalls

  1. --login-server will not connect

    Check that the URL is complete, includes https, and is reachable from outside; open the same URL in a browser to test (a Headscale control server does not necessarily serve a web page, but this confirms DNS and the certificate).

  2. The key is rejected

    The key may have expired, may already have been used (single-use), or may be bound to the wrong user. Generate a new one.

  3. The client has already logged into an official account

    Run tailscale logout to log out of the official service first, then run tailscale up --login-server ... again.

  4. The node does not show up in nodes list

    Wait a few seconds for the client to finish registering; if it is still missing, go back to the device and read the error message from tailscale status.

Joining FAQ

Do I have to use a preauth key?
Not necessarily. You can also use the interactive login (browser authorization). A preauth key suits headless devices and automation; the interactive login suits devices with a screen.
Can one device connect to the official service and to Headscale at the same time?
At any one moment it normally connects to a single control server. To switch, run tailscale logout first, then connect to the other one.
Does a device get a fixed address after it joins?
It is assigned a tailnet IP address, which is usually stable but is not guaranteed to stay the same forever. For identifying a device to others, the node name is more reliable.
How does the phone app connect to a self-hosted server?
The app's login screen usually has a "Use custom server" option; enter your Headscale URL there and you are done.
Joined, but they still cannot reach each other?
The default ACL may not allow that traffic yet; that is the access control Chapter 7 covers. First confirm that every node is online.
