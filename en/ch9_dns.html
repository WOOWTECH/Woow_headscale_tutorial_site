Chapter 9

DNS and MagicDNS

Connect to devices by name instead of memorizing IP addresses. By the end of this chapter, you'll understand how MagicDNS resolves a node name into a tailnet IP address, and how to set up custom DNS and split DNS.

Names beat IP addresses

Once a tailnet holds more than a few devices, remembering IP addresses stops being practical. MagicDNS lets you connect straight to a device by its name (such as nas, living-room), exactly as you would with an IP address, but far easier to remember.

Chapter task: understand how MagicDNS works, how to connect by name, and what custom DNS is for.

What MagicDNS is

MagicDNS is the "name resolution" service the control server provides: it gives every node a name you can remember, and resolves that name into a tailnet IP address. Ping nas and you are pinging that device.

ConceptWhat it means
Node nameThe hostname each device carries inside the tailnet
MagicDNSThe mechanism that resolves a name into a Tailscale IP address
split DNSHands only certain domains to a specific DNS server for resolution
The control server must see the name: the node name is set on the client side; the control server records it and serves it to MagicDNS for resolution.

Five steps to connect by name

  1. Confirm MagicDNS is enabled

    In the control server's DNS settings, confirm that MagicDNS is on (the relevant Headscale settings).

  2. Give each device a proper name

    Give every device a clear hostname (such as nas, or living-room for the living room), not a default name that is hard to remember.

  3. Connect by name

    From another node, run ping nas or ssh living-room (the living-room host) and see whether the name resolves correctly.

  4. Set up split DNS if you need it

    Send resolution for your company's local network, or for particular domains, to a specific DNS server, and leave everything else on the default.

  5. Check for clashes

    Do not let a node name clash with a hostname that already exists on your local network, so resolution stays unambiguous.

Custom DNS and split DNS

  • Custom DNS: the DNS server you tell the devices in the tailnet to use (a Pi-hole or AdGuard on your local network, for example).
  • split DNS: hands only "certain domains" to a specific server for resolution, for example internal.example.com on your company's local network, and leaves the rest of the traffic untouched.
  • What it is for: ad blocking, name resolution for services on your local network, and keeping resolution policies for different domains apart.
DNS changes affect every node: DNS settings live at the control server level, so a change reaches the whole tailnet. Confirm before you change anything, and keep a backup.

Common DNS pitfalls

  1. A name does not resolve

    Check that MagicDNS is enabled, that no two node names clash, and that the other node is online.

  2. A name resolves to the wrong device

    Two nodes share a name, or an old name has not been updated. Check them and rename.

  3. Custom DNS has no effect

    Confirm the setting has been applied and refresh DNS on the node; some changes need the node to reconnect.

  4. A name clashes with a local service

    A node name collides with a hostname on your local network. Switch to a name that does not clash, or adjust split DNS.

DNS FAQ

Is MagicDNS required?
No. You can connect by IP address alone. But connecting by name is far more convenient, so we recommend turning it on.
Can a node name use Chinese characters?
That depends on what the client and the control server support. Most environments handle it, but an alphanumeric hostname is the safer choice for compatibility.
How is split DNS different from ordinary DNS?
Ordinary DNS sends everything to the same server; split DNS routes only certain domains to a specific server and leaves the rest as it was.
Can I hook up a Pi-hole to block ads?
Yes. Point the tailnet's custom DNS at the Pi-hole and every node's resolution goes through it, so ads are blocked.
After a rename, does the old name still work?
Once you rename a node the old name usually stops working, so connect with the new one; some caches may take a while to update.
