第 3 章

第一次開啟與登入

認識 Headscale 的管理方式——它主要以命令列（CLI）與 API 操作，部分環境才有 Web UI。讀完這章，你會確認版本與狀態、認得基本命令，並知道控制層為什麼不能對外亂開。

控制層長得跟你想的不一樣

前面幾套服務（相簿、雲端）都有漂亮的圖形介面；Headscale 不一樣，它是「後台型」服務，管理動作多半靠命令列（CLI）與API。先認清這件事，才不會一直找「設定按鈕」找不到。

本章任務：進入控制層的終端、確認版本與狀態、認得幾個基本命令。全程唯讀，不建立任何東西。

三種管理方式

方式長什麼樣適合誰
命令列（CLI）在終端打 headscale 開頭的命令主要管理方式，功能最完整
API用程式／腳本呼叫 HTTP 介面自動化與整合
Web UI（若有）圖形介面看狀態、部分部署才有
心態調整：把 Headscale 想成一台「要打指令的伺服器」，而不是「點來點去的 App」。命令熟了其實很快。

五步確認版本與狀態

  1. 進入 add-on 終端

    在 Home Assistant 的 Headscale add-on 頁，找到「終端（Terminal）」入口（或透過 SSH 連進主機），進入命令列。

  2. 確認版本

    輸入 headscale version，會顯示目前 Headscale 的版本號。

  3. 看有哪些使用者

    輸入 headscale users list，列出目前的使用者（namespace）。全新安裝可能只有預設項。

  4. 看有哪些節點

    輸入 headscale nodes list，列出已加入的節點。剛裝好通常還是空的。

  5. 看日誌確認運作

    回 add-on 的「日誌（Log）」分頁，確認沒有反覆錯誤、服務持續運作。

命令要在對的環境：headscale 命令要在 add-on 的容器內或主機的 headscale 執行環境裡才有。打錯環境會出現「找不到指令」。

基本命令速查

命令做什麼對應章節
headscale version顯示版本本章
headscale users list列出使用者第 4 章
headscale users create建立使用者第 4 章
headscale preauthkeys list列出預授權金鑰第 4 章
headscale nodes list列出節點第 6 章
善用 --help：不確定某個命令怎麼用，打 headscale <子命令> --help 就有說明。養成先看 help 的習慣。

控制層為什麼不能對外亂開

控制層是整張網的「大腦」：節點清單、ACL、金鑰都在這。它一旦被外人碰到，你的私有網段就等於被接管。因此：

  • 管理介面（CLI／API／Web UI）只留給管理員，不對外公開。
  • client 要連的是「加入用的入口」，不是把整個管理介面暴露到公網。
  • 需要對外時，走 Cloudflare Tunnel 這類加密通道，而不是直接開 port。
停止線：不要為了「遠端方便」把 Headscale 管理介面直接公開到網際網路。遠端管理要走安全通道＋最小權限。

第一次開啟常見卡關

  1. 找不到終端入口

    不同 add-on 提供的終端位置不同。找 add-on 頁的「Terminal／終端」，或問管理員怎麼進 CLI。

  2. 打 headscale 說找不到指令

    你不在正確的執行環境。確認進入的是 add-on 容器終端，或 headscale 已裝在主機。

  3. 命令回報權限不足

    部分操作需要足夠權限。用對的身分執行，或請管理員處理。

  4. 沒有 Web UI 覺得不習慣

    Headscale 以 CLI/API 為主，Web UI 是選配。先習慣 CLI，後面章節都用命令。

第一次開啟常見問題

為什麼 Headscale 沒有漂亮介面？
它是「控制層」後台，重點是管節點與 policy，不是給日常操作。日常上網、連裝置靠 client 端（tailscale），不用整天看控制層。
一定要會打指令嗎？
做管理動作（建使用者、發金鑰）需要；日常使用（裝置互連）幾乎不用碰控制層。指令其實不多，照著打即可。
Web UI 是什麼？
有些部署會另外裝 headscale-ui 等圖形介面，用來「看」狀態較方便；但完整管理還是以 CLI/API 為主。
headscale version 顯示的版本重要嗎？
重要。排錯、查功能時要對版本；client 端也要能相容。版本不一致有時是問題來源。
我可以把控制層開給家人用嗎？
控制層只給管理員。家人用裝置加入網段即可（第 5 章），不需要碰到控制層。
